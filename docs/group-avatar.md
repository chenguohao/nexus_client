# 群头像显示规则 (Group Avatar Display Rule)

本文档描述群聊在「聊天列表」「聊天顶部栏」等处的头像展示逻辑。
实现位于 `lib/widgets/avatar/room_avatar.dart`（`RoomAvatar` widget）。

## 一、为什么不做「九宫格拼图」

微信群的默认头像是把前 N 个成员头像拼成九宫格。在我们的场景下：

- 群可能很大（成百上千人），拼图无法代表整个群，只能抽样展示几个人。
- 拼图随着成员进出、头像更换会**不断抖动**，列表视觉非常不稳定。
- 没头像的人一多，拼图很容易变成一堆灰色占位，观感糟糕。

所以我们采用**「3 个成员头像 + 一个人数角标」**的方案：既有人味、又有规模感，
并通过稳定的成员选取规则避免抖动。

## 二、显示优先级

1. **群管理员设置了群头像** → 直接显示群头像（单图）。
2. **未设置群头像** → 显示「3 人头像 + 人数角标」的默认群头像（2×2 田字格）。
3. **一对一私聊** → 使用原有的单张头像 / 首字母占位（不走拼图逻辑）。

> 只要群头像一旦被设置，**永久覆盖**默认拼图，直到被清除。

## 三、默认群头像的布局

- 整体为正方形，圆角 `4px`，与单头像一致。
- 2×2 田字格，共 4 格，格间距 `1.5px`：
  - 左上 / 右上 / 左下 = 最多 3 个成员头像（成员不足时留空）
  - **右下永远 = 群总人数徽标**（深灰底 + 数字）

```
┌──────┬──────┐
│  U0  │  U1  │
├──────┼──────┤
│  U2  │  N   │   ← N = 群总人数（actualMembersCount）
└──────┴──────┘
```

## 四、「前三个成员」选谁

核心诉求：**稳定** + **有意义**，避免大群里头像抖动。

选择规则：

1. **候选集合**：`Membership.join` + `Membership.invite`（已加入的 + 被邀请但未接受的）。
   这样跟群信息页显示的 "X members"（`room.summary.actualMembersCount`）口径一致，
   不会出现「群里 3 个人但头像只显示 2 + `+1`」这种撕裂。
2. **群创建者（creator）永远排在第 1 位**（如果仍在群里）。
3. 其余按下列顺序排序：
   - `powerLevel` 降序（群主 → 管理员 → 普通成员）
   - `matrixId` 升序（同权限下的稳定 tiebreaker）
4. 取排序后的**前 3 人**。

若候选人**没有头像**，保留其位置但显示 `AvatarGradientPlaceholder`
（**彩色渐变底 + 姓名首字母**，和聊天列表单头像占位一致），不使用灰色人形剪影。

> ⚠️ 成员占位用**彩色渐变底**，`+N` 人数角标用**深灰底**，两者视觉上必须
> 区分开——否则名字以数字开头的用户（例如 `6ebbjp`，首字母占位就是 "6"）
> 看起来会和 `+6` 这种角标难以分辨。

## 五、人数徽标

- **右下格永远显示群总人数**，不是"`+N` 差额"。这样用户在列表一眼就能判断
  "这群几个人"，对小群和大群都适用。
- 数值来源：`room.summary.actualMembersCount`（joined + invited）。
- 显示格式：纯数字，例如 `3`、`11`、`99+`。
- `N ≥ 100` 时封顶显示 `99+`，避免撑破格子。
- 字号随字符数自适应：2 位数 `≈ size × 0.36`，3 位数 `≈ size × 0.28`；
  白字、字重 700。
- 背景是**深灰**；成员占位用**彩色渐变底**（见 §四），两者颜色必须不同，
  避免名字以数字开头的成员（例如 `6ebbjp` 首字母 "6"）被误认成徽标。

## 六、边界情况

| 情况                       | 处理                                              |
| -------------------------- | ------------------------------------------------- |
| 群只有 1 个人              | 左上 1 格显示该成员，其余留空占位，右下显示 `1`   |
| 群只有 2-3 个人            | 依序填格，剩余成员格留空占位，右下显示总人数       |
| 前 3 人都没有头像          | 用彩色渐变底占位，不使用灰色人形剪影              |
| 创建者已经退群             | 回落到 powerLevel 排序，结果依旧稳定              |
| 成员退群导致「前 3」变化   | UI 下次重建时自动反映（依赖列表层的刷新机制）     |
| 超大群（上千人）           | 右下角 ≥ 100 统一显示 `99+`                       |

## 七、性能与刷新

- `RoomAvatar` 本身是 `StatelessWidget`，内部的 `_GroupGridAvatar`
  是 `StatefulWidget`，用来处理一次性的「懒加载成员」。
- **成员懒加载**：Matrix SDK 默认只把 *当前用户 + heroes* 放进本地状态，
  其他成员要等 `room.requestParticipants(...)` 才会进内存。
  - `_GroupGridAvatar` 在 `initState` 检查 `cachedCount < totalCount`，
    若成立就调一次 `requestParticipants([Membership.join], false, true)`
    （`cache=true` 让 SDK 自己缓存，不会反复拉）。
  - 用一个 widget 级别的静态集合 `_requestedRoomIds` 去重，防止
    多个 `RoomAvatar` 同时 fire 同一个房间的请求。
  - 请求完成后 `setState` 触发重建，显示完整的前 3 人。
- 「总人数」来源统一用 `room.summary.actualMembersCount`
  （= `mJoinedMemberCount + mInvitedMemberCount`），跟聊天详情页等地方保持一致。
  之前用 `mJoinedMemberCount` 会在列表未同步完时为 `null`，导致 `+N` 不出现。
- 每个成员 cell 内部使用 `MxcImage(isThumbnail: true)` +
  `cacheWidth = cellSize * devicePixelRatio * 2`，避免按原图分辨率解码。
- `MxcImage` 用 mxc URL 作为 `cacheKey`，单元格之间的图片缓存与单头像共享。
- 聊天列表里外层 `RoomAvatar` 设置了 `keepAlive: true`（与原先 `Avatar` 一致），
  避免滚动时反复拉取头像。

## 八、可扩展点（后续可做）

- 允许群主/管理员通过设置页**重置为默认头像**，清空自定义头像字段后即自动
  回到本规则。权限：仅 `powerLevel >= admin` 可修改。
- 如果未来需要在「聊天详情页大 header」里也用拼图（目前是大封面 hero 图），
  可以把 `RoomAvatar` 扩展一个 `heroStyle: true` 变体。
- 如果要在通知、桌面角标等小尺寸场景复用，直接用 `RoomAvatar` 并传入
  对应 `size` 即可，格子会按比例自适应。
